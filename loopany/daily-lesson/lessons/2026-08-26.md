## Track A · Rust

### Concept

`if let` is a `match` with one arm and no `_`. The left side is a **pattern**:

```rust
if let Some(word) = optional_target { /* word is the value inside */ }
while let Some(x) = stack.pop()     { /* stops on the first None */ }
```

Two things bite in these files. `Vec::pop` on a `Vec<Option<i8>>` hands back
`Option<Option<i8>>` — the pattern has to **nest**. And a `match` on a value *moves* it, so
anything printed afterwards has to have been matched by reference.

## Track B · DSA

### Concept

Alpha-beta's whole saving comes from finding a cutoff early, and it finds one early only if
the good move is searched first. So the pruning you get is not a property of alpha-beta — it
is a property of **the order you hand it the moves in**.

Two extremes, both at branching factor `b` and depth `d`:

- **Worst order** — every good move searched last. No cutoffs ever fire. You pay the full
  `b^d`, plus the bookkeeping. Alpha-beta bought you nothing.
- **Perfect order** — best move first at every node. Alpha-beta examines about

  ```
  2 · b^(d/2) − 1
  ```

  nodes instead of `b^d`. That exponent is *halved*. Same node budget, roughly twice the
  depth.

Real engines don't get perfect order, they get close with three cheap guesses, tried in this
sequence: **the transposition table's move** for this position (a real search result, not a
guess), then **captures ranked MVV-LVA** — most valuable victim, least valuable attacker, so
pawn-takes-queen outranks queen-takes-pawn — then everything else. A capture that loses
material is not a good move just because it's a capture.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1 (a)** `4⁴ = 256`. **(b)** `2·4⁴ − 1 = 511`. **(c)** For about twice the nodes you got
**twice the depth** — 511 nodes at depth 8 against 256 at depth 4. Unordered, depth 8 would
have been `4⁸ = 65,536`. Ordering is worth more than any evaluation tweak at this stage.

**Q2.** **(d) the TT move first** — it isn't a heuristic, it's the answer a previous search
already computed for this exact position; if anything causes a cutoff, it's that. **(b) PxQ
next** — MVV-LVA's best case: richest victim, cheapest attacker, and even if the pawn is lost
you're up a queen for a pawn. **(a) the quiet knight move**, then **(c) QxP last** — a
*losing* capture. Queen for a defended pawn is material thrown away; being a capture doesn't
rescue it, and searching it early just wastes the first slot.

</details>
