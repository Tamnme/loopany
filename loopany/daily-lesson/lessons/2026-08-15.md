### Concept

A `HashMap<K, V>` stores key → value with no order at all. `insert` adds or overwrites; `get`
hands back an `Option<&V>`, because the key might simply not be there:

```rust
use std::collections::HashMap;

let mut basket: HashMap<String, u32> = HashMap::new();
basket.insert(String::from("banana"), 2);

match basket.get("banana") {
    Some(n) => println!("{n} bananas"),
    None => println!("none in the basket"),
}
```

Two things fall out of that. Keys have to be hashable and comparable — for your own type that
means `#[derive(Hash, PartialEq, Eq)]`, which `hashmaps2` already does for you. And when you
only want to know *whether* a key is present, `contains_key(&k)` answers it without unwrapping
an `Option`.

## Track B · DSA

### Concept

A bitboard is one `u64` — 64 squares, 64 bits. Bit `i` *is* square `i`, same numbering as your
`Square`: `index = rank * 8 + file`, bit 0 is a1, bit 63 is h8. Set means "a piece is here".

The payoff is that `count_ones()` gives you a material count in one instruction, and a shift
moves a whole army at once: `pawns << 8` advances every white pawn one rank, no loop.

The catch is edges. `<< 8` is safe — bits pushed past 63 fall off, and pawns can't leave the
board anyway. Sideways is not safe. The board is only *drawn* as a grid; to the CPU it's a
single 64-digit number that has no idea rank 1 ends at h1. Shift a bit off one edge and it
reappears on the opposite file of the neighbouring rank.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1.** a8 = `7*8 + 0` = **56**, h8 = `7*8 + 7` = **63**. Popcount **2**.

**Q2.** `>> 1` gives bits **55** and **62**.

62 → rank 7, file 6 → **g8**. Correct: the h8 rook stepped one square west.

55 → rank 6, file 7 → **h7**. Wrong. The a8 rook had no square west of it, so instead of
falling off the board the bit wrapped to the far end of the rank below. Nothing on the a-file
may shift west, so you delete that file first:

```
(bb & !FILE_A) >> 1
```

East shifts mask `FILE_H` the same way. That pair of masks is why every real move generator
keeps a small table of file constants around.

</details>
