## Track A · Rust

### Concept

`pop` has to answer two questions with one value: *is there anything here*, and *if so, what*.
That is the whole job of `Option` — `None` answers the first question, `Some(x)` answers both.

The tool you need on the `Vec` side:

```rust
fn remove(&mut self, index: usize) -> T   // panics if index is out of range
```

`remove(0)` hands back the front element and shifts everything after it down one slot. That
shift is the `O(n)` this `Queue` pays on purpose — the `O(1)` ring-buffer version wants
`Option::take` and a head index, neither of which is taught yet. Note it **panics** on an empty
`Vec`, so the emptiness question gets asked first, not second.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1.** `Option<Piece>` has no field `kind` — the `Option` is a box around the piece, and the
square might be empty. Either `match` it (`Some(p) => p.kind`, `None => …`) or `.unwrap()` when
you're certain and it's a test.

**Q2.** Nothing is written until a call *returns*, and the descent `5→4→3→2` bottoms out first:
`memo[2]=1, memo[3]=2, memo[4]=3, memo[5]=5`. A transposition table is **top-down** — a search
touches a thin slice of all legal positions, so you fill it lazily by descending, never
bottom-up.

**Q3.** `bb << 8` moves every piece one rank **up** (toward rank 8) — that's how a white pawn
push is generated for all pawns at once. `bb & 0xFF` keeps bits 0–7, which is rank 1.

**Q4.** Capacity **doubles** to 8. Amortized cost is **`O(1)`**. Doubling means the copies get
rarer exactly as fast as they get more expensive: growing to `n` copies `1+2+4+…+n < 2n`
elements in total, so about 2 copies per push no matter how large `n` gets. `O(n)` is the cost
of the one unlucky push that reallocates, not the average.

</details>
