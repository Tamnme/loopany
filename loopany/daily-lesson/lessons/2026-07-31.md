### Concept

You don't need to know Rust to fix a Rust error. The compiler tells you the file,
the line, and usually the fix. That's the whole skill today: run it, read the
first error, change what it points at.

```
error: cannot find macro `printline` in this scope
 --> exercises/00_intro/intro2.rs:12:5
   |
12 |     printline!("Hello there!");
   |     ^^^^^^^^^ help: a macro with a similar name exists: `println`
```

Everything you need is in there — the arrow line is the file and line number, and
`help:` is literally the answer. Rust's error messages are unusually good, and
leaning on them is normal practice, not cheating.

(`println!` ends in `!` because it's a **macro**, expanded at compile time — that's
also why the compiler can check your format string.)

### Concept

Big-O answers one question: **when the input gets bigger, how fast does the work
grow?** Not "how many milliseconds" — machines differ. Only the growth shape.

The trick for reading it: **double the input, ask what happens to the work.**

```
n items                     work        double n → work becomes
------------------------------------------------------------------
look at the first item      1           1              → O(1)
walk the list once          n           2n             → O(n)
for each item, walk again   n²          4n²            → O(n²)
```

That's why constants and smaller terms get dropped: `3n + 50` still merely
*doubles* when `n` doubles, so it's `O(n)`. `n² + 1000n` quadruples, so the `n²`
wins and it's `O(n²)`. You keep only the term that dominates as `n` grows.

Worked trace — what's the Big-O here?

```
total = 0
for each x in list:          # runs n times
    for each y in list:      # runs n times, for every x
        total = total + 1
```

Inner body runs `n × n` times → `O(n²)`. Double the list, the work goes up 4×.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1 — `O(n)`.** Two separate loops, `n` prints each, so `2n` total. Double `n`
and the work merely doubles. Constants are dropped: `2n` → `O(n)`. The common
mistake is seeing two loops and saying `O(n²)` — that only happens when one loop
is *nested inside* the other.

**Q2 — `O(1)`.** Exactly two prints no matter how long the list is. A million
items, still two prints. Constant work → `O(1)`.

**Q3 — `O(n²)`.** The input doubled (1,000 → 2,000) and the time went up 4× (1s →
4s). `O(n)` would have given 2 seconds; `O(1)` would have stayed at 1 second.
Quadrupling on a doubled input is the signature of `n²`.
</details>
