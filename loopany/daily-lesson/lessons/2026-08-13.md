## Track A · Rust

### Concept

Files don't become part of your crate on their own. A file is only compiled if some module
**declares** it:

```
src/chess.rs          contains  pub mod piece;   ← the declaration
src/chess/piece.rs    the file it names
```

Without that line, `src/chess/piece.rs` is just text on disk — no error, no warning, and any
tests inside it silently never run. That's the trap: a missing `mod` doesn't fail, it goes
quiet.

The second half is `pub`. Everything in Rust is private to its module by default — a `fn`, a
`struct`, and each **field** of that struct separately. `pub` is what lets the module next
door see it. That's all `modules1` is asking you to fix.

## Track B · DSA

### Concept

**Recursion** is a function that calls itself on a *smaller* version of the problem. Two
parts, always:

- a **base case** — small enough to answer outright, no call
- a **recursive case** — do a bit of work, call yourself on something strictly smaller

Miss the base case and it never stops; the stack fills and the program dies. Fail to shrink
the input and you get the same thing.

Chess uses this twice, and both are the same shape. **Perft** counts the leaf positions
reachable in `depth` moves — it's how you prove move generation is correct:

```
perft(pos, depth):
    if depth == 0:                       # base case
        return 1
    total = 0
    for m in legal_moves(pos):
        total += perft(pos + m, depth - 1)   # smaller: depth - 1
    return total
```

**Minimax** at phase 5 is that function with `+=` swapped for "take the best" — same
recursion, different combiner. **Divide-and-conquer** is the same idea one step up: split
into independent subproblems, recurse on each, combine the answers. Merge sort, yesterday,
was exactly that — split, sort both halves, merge.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1.** **27**. Level 1 has 3 positions, level 2 has 3 × 3 = 9, level 3 has 27. Each of those
27 hits `depth == 0` and returns `1`, and the `+=` chain adds them up — so the base case runs
**27 times**, once per leaf. The return value and the base-case count are the same number,
which is the point: perft *is* a leaf count.

**Q2.** **`O(b^d)`** — each level multiplies the number of positions by `b`, and there are `d`
levels, so the leaves are `b × b × … × b`, `d` times. This is exponential, not polynomial:
adding one to the depth multiplies the whole cost by `b`.

At `b = 35`, `d = 5`: `35⁵ ≈ 52,500,000` — about **50 million** positions. That's why phase 5
needs alpha-beta. It doesn't make the tree smaller; it proves whole branches can't affect the
answer and never visits them.

</details>
