### Concept

`match` compares a value against every shape it can have, and the compiler checks you
covered all of them. Miss a variant and it won't build — that's the feature, not the tax.

```rust
enum Shape { Circle(f64), Rect { w: f64, h: f64 }, Empty }

fn area(s: Shape) -> f64 {
    match s {
        Shape::Circle(r) => 3.14 * r * r,
        Shape::Rect { w, h } => w * h,
        Shape::Empty => 0.0,
    }
}
```

Each arm **destructures**: the names on the left (`r`, `w`, `h`) bind to the data inside
that variant, ready to use on the right. And like `if`, `match` is an expression — every
arm yields the same type, or `()` when the arms just call methods.

## Track B · DSA

### Concept

A **graph** is just vertices and the edges between them. No root, no order, no shape rules
— a tree is a graph with restrictions, not the other way round. Edges may be **directed**
(one-way) or not.

Two ways to store one, and the choice is the whole lesson:

```
  A —— B        adjacency list        adjacency matrix
  |  / |        A: [B, C]               A B C D
  | /  |        B: [A, C, D]          A 0 1 1 0
  C —— D        C: [A, B, D]          B 1 0 1 1
                D: [B, C]             C 1 1 0 1
                                      D 0 1 1 0
```

A **list** stores each vertex's neighbours: `O(V + E)` space, and "who are A's neighbours?"
is instant — but "is A—D an edge?" means walking A's list.

A **matrix** is a `V × V` grid of yes/no: "is A—D an edge?" is one lookup, `O(1)`. The
price is `V²` cells whether the edges exist or not — 1,000 vertices costs a million cells
even if there are only ten edges.

So: **lists for sparse graphs, matrices for dense ones.** Most real graphs are sparse, so
the list is the default.

Chess needs this later. The search "tree" isn't a tree — the same position is reachable by
different move orders, so it's a graph, and noticing that two paths landed on one node is
exactly what the transposition table at phase 7 does.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1.** Root `2` leaves. The last element, `4`, takes its place: `[4, 5, 3, 8, 9]`. The
children of index 0 are `5` and `3`; the smaller is `3`, and `3 < 4`, so swap →
`[3, 5, 4, 8, 9]`, now at index 2. Index 2 has no children, so stop. Final:
**`[3, 5, 4, 8, 9]`**.

`O(log n)` because a sink only ever walks one root-to-leaf path, and a complete tree of `n`
nodes is `log₂ n` levels deep — 20 steps at a million items, not a million.

**Q2.** ~5,000 edges. Adjacency **list**: `O(V + E)` = 1,000 + 5,000 ≈ **6,000** entries.
Adjacency **matrix**: `V²` = **1,000,000** cells, 99.5% of them zero. Sparse graph → list.

</details>
