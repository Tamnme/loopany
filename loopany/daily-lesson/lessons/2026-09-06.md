## Track A · Rust

### Concept

`ds::Graph` is new but the idea isn't — you traced graphs by hand on 11 Aug. An **adjacency
list** stores, per vertex, only the vertices it actually touches: `Vec<Vec<usize>>`, one inner
`Vec` per vertex. Memory is O(V + E) instead of a matrix's O(V²).

"Undirected" is not a flag — it's a fact you have to maintain. Adding edge `a–b` means pushing
`b` into `a`'s list *and* `a` into `b`'s. Nothing enforces it for you.

Forget the second push and the graph is quietly directed, and every traversal gives half an answer.

<details>
<summary>Worked answers — open only after you've written yours</summary>

**Q1.** Any function whose return type isn't `Result` (or `Option`) — `fn main()` without a
return type, say. `?` returns the error *from the enclosing function*, so that function must
have somewhere to put it. The error is "the `?` operator can only be used in a function that
returns `Result`".

**Q2.** An asymmetric make/unmake — one XOR done on the way in and not on the way out
(castling rights and the en-passant key are the usual suspects). XOR is its own inverse, so
the two paths must be the *identical* set of XORs.

**Q3.** Anything where the caller must act differently per failure. `parse` returning `None`
can't distinguish "empty input" from "not a number" from "overflow" — `Result` carries the
reason, `Option` throws it away.

**Q4.** A **sparse** graph: many vertices, few edges (a road network, a chess game tree). The
matrix costs O(V²) *memory* whether or not the edges exist — 100k vertices is 10^10 cells,
almost all zero. Time per lookup is actually better in a matrix; memory is what kills it.

**Q5.** `[2, 5, 3, 8, 9, 4]`. Append `4` at the end, then sift up: its parent is index
`(5-1)/2 = 2`, holding `3`, and `4 > 3`, so it already sits below its parent and stops there.
Zero swaps. Insert touches one root-ward path, never the whole array — that's the O(log n).

</details>
