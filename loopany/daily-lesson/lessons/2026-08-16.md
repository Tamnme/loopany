## Track A · Rust

### Concept

`src/ds/queue.rs` now exists, declared and compiling. A queue is a stack turned around: a
stack hands back the **newest** item, a queue hands back the **oldest**. That's the whole
difference, and it's why `pop` looks at the front rather than the back.

The struct is written for you, including the generic `<T>` you haven't formally met — read it,
don't worry about it. `Queue<T>` just means "a queue of *some* type, decided at the call site",
exactly like `Vec<T>`.

```rust
pub struct Queue<T> {
    items: Vec<T>,
}
```

`new` is given. Three bodies are `todo!()`.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1.** a2 = `1*8 + 0` = **8**, h2 = `1*8 + 7` = **15**. Popcount **8**. `pawns << 8` adds 8 to
every index — the whole army advances one rank, in one instruction, no loop.

**Q2.** `pub use` **re-exports**: outsiders can now write `mymod::Thing` even though `Thing`
really lives in `mymod::inner`. Plain `use` is private to the module — it only shortens the
name for code inside that file.

**Q3.** Big-O describes the *growth rate*, not the cost at a given size. At `n = 30`, `n²` is
900 tiny operations with almost no bookkeeping, while merge sort allocates and copies. Insertion
sort also runs near-linear on already-mostly-sorted input, which move lists usually are.

**Q4.** A **collision**. Average lookup stays **O(1)** — the bucket holds a handful of entries,
so you scan a constant number of them. Only a pathological hash degrades it to `O(n)`.

**Q5.** Many `&` **or** exactly one `&mut` — never both at once. Either any number of readers,
or a single writer. That rule is what makes data races impossible to compile.

</details>
