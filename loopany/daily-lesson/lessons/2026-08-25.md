## Track A · Rust

### Concept

`if let` is a `match` with one arm you care about and no `_` to write.

```rust
if let Some(word) = optional_target {
    // `word` is the value inside — and only in here
}
```

The left side is a **pattern**, not a variable. `Some(word)` matches only when the `Option`
is `Some`, and binds what's inside to `word`. On `None` the block is skipped.

`while let` is the same trick in a loop — keep going while the pattern still matches:

```rust
while let Some(x) = stack.pop() {
    // stops the first time pop() returns None
}
```

That's how you drain anything that hands values back as `Option`.

## Track B · DSA

### Concept

A search wants depth 4. Iterative deepening searches depth 1, throws it away, searches depth
2, throws it away… up to 4. That sounds like paying four times. It isn't, and the reason is
just the shape of a tree.

With branching factor `b`, depth `d` holds about `b^d` nodes. Each level is `b` times bigger
than the one above it, so the **last level dwarfs everything above it combined**. All the
discarded shallow searches together cost roughly `1/(b-1)` of the real one.

Chess has `b ≈ 30`. So the throwaway work is a few percent — and in exchange you get the
previous depth's best move to try *first* at the next depth, which is exactly what alpha-beta
needs to prune well.

**Q1 (a)** 4, 16, 64, 256. **(b)** `4+16+64 = 84`, so `84/256 ≈ 33%`. **(c)** Smaller:
`30+900+27000 = 27930` against `810000` ≈ **3.4%**, which is `1/29`. The bigger the fan-out,
the more the bottom level dominates, so re-searching everything above it gets *cheaper*, not
dearer.

**Q2.** Either counts. **Move ordering** — depth `d-1`'s best move is searched first at depth
`d`, and alpha-beta's savings depend almost entirely on trying the best move first. Or
**anytime behaviour**: you always have a legal, fully-searched move in hand, so the clock can
stop you at any moment.
