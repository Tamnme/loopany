## Track A · Rust

### Concept

Rust's `if` has two surprises for anyone arriving from Python, JS or C.

**No parentheses, and the condition must be a real `bool`.** There is no truthiness —
`0`, `""` and empty collections are not false, they're type errors.

```rust
if count > 0 { … }        // no parens around the condition
if count { … }            // error: expected `bool`, found integer
```

**`if` is an expression — it produces a value.** So you assign from it directly, no
mutable placeholder needed:

```rust
let label = if score >= 50 { "pass" } else { "fail" };
```

Two rules come with that. Both arms must have the **same type** (`"pass"` and `fail`
without quotes won't compile), and the arms use the same no-semicolon rule you learned
yesterday — the last expression in each block is that arm's value.

```rust
let n = if flag { 1 } else { 2 };     // ok
let n = if flag { 1; } else { 2; };   // both arms are () → type error
```

That's why Rust needs no ternary `? :` operator: `if` already is one.

### Concept

A **stack** is not a new shape of memory — it's a *discipline* imposed on one you
already know. One rule: **last in, first out (LIFO)**. You may only touch the top.

Three operations, and that's the whole interface:

| op | meaning | cost |
|---|---|---|
| `push(x)` | put `x` on top | `O(1)` |
| `pop()` | remove and return the top | `O(1)` |
| `peek()` | look at the top without removing | `O(1)` |

Everything is `O(1)` *because* of the restriction. There is no "insert at index 3", no
search, no shifting — so nothing can cost more than a constant.

```
push 3    push 7    push 1     pop → 1    pop → 7
 ┌───┐     ┌───┐     ┌───┐      ┌───┐      ┌───┐
 │   │     │   │     │ 1 │←top  │   │      │   │
 │   │     │ 7 │←top │ 7 │      │ 7 │←top  │   │
 │ 3 │←top │ 3 │     │ 3 │      │ 3 │      │ 3 │←top
 └───┘     └───┘     └───┘      └───┘      └───┘
```

**Both of last week's structures can back it.** With a dynamic array, the top is the
**end** — `push` is an append, `pop` is a truncate, both amortized `O(1)`, and the
elements stay contiguous and cache-friendly. With a linked list, the top is the
**head** — `push` is a front insert, `pop` is a front delete, both worst-case `O(1)`,
but each element pays for a pointer and a scattered allocation. Notice the array
version deliberately avoids index 0, the one end where an array is slow. That's the
whole trick: *pick the end each structure is fast at.*

Where stacks actually show up: the **call stack** (every function call pushes a frame,
every `return` pops one — that's why infinite recursion is a *stack* overflow), undo
history, the browser back button, matching brackets in a parser, and depth-first search
on a graph, which you'll meet in a few weeks.

<details>
<summary>Worked answer — open only after you've written yours</summary>

**Q1 — you need the *previous* node, and finding it costs `O(n)`.** Deleting node `X`
means making `X`'s predecessor point at `X.next`. A singly linked node only knows what
comes *after* it, so the only way to the predecessor is to walk from `head` again. That
is why "delete this node" is `O(n)` in a singly linked list even when you're already
holding the node. Two standard fixes: a **doubly linked list** (each node also stores
`prev` → `O(1)`, at the cost of another pointer per node), or the copy trick — copy the
*next* node's value into `X` and delete the next node instead, which works for every
node except the last.

**Q2 — bottom to top: `4, 2, 5`; the top is `5`.** Trace it: `4` → `4,9` → pop removes
`9` → `4,2` → `4,2,6` → pop removes `6` → `4,2,5`. The two `pop`s each took the most
recent push, never the oldest — that's LIFO, and it's why `9` and `6` vanished while
`4` sat untouched at the bottom the entire time.

**Q3 — the end. Front would make `push` `O(n)`.** Inserting at index 0 shifts all `n`
existing elements up one slot, every single push. Appending at the end writes one slot
and is amortized `O(1)` (amortized, not worst-case, because of the occasional doubling
you costed out in lesson 3). So an array-backed stack grows at the end, and the "top"
is simply the last element — which is exactly what Rust's `Vec::push` / `Vec::pop` do,
and why `Vec` *is* the idiomatic stack in Rust.

**Q4 — push every opening bracket; on a closing bracket, pop and check it matches.**
The bracket a closer must match is always the **most recent unmatched opener** — that's
LIFO, so a stack is not just *a* fit, it's the exact shape of the problem. Walking
`([]{})`: push `(`, push `[`, see `]` → pop gives `[` ✓, push `{`, see `}` → pop gives
`{` ✓, see `)` → pop gives `(` ✓, end with an empty stack → balanced. Two failure
modes fall out for free: popping a *mismatched* opener, and finishing with a non-empty
stack (unclosed openers) or trying to pop an empty one (a closer with no opener).
</details>
