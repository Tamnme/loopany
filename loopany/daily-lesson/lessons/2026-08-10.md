## Track A · Rust

### Concept

A struct's data and its behaviour live in the same place. Data goes in the `struct`,
behaviour goes in an `impl` block beside it:

```rust
struct Package { grams: u32 }

impl Package {
    fn new(grams: u32) -> Self { Self { grams } }   // no self: an associated function
    fn fees(&self, per_gram: u32) -> u32 { self.grams * per_gram }  // takes &self: a method
}

let p = Package::new(1500);   // :: for associated functions
p.fees(3);                    // .  for methods
```

The difference is the first parameter. `&self` borrows the value you call it on — that's
yesterday's `&` again, so `p` stays usable afterwards. No `&self` means the function just
belongs to the type's namespace; `new` is the usual case, since there's no value yet.
`Self` (capital) is shorthand for the type you're inside.

## Track B · DSA

### Concept

A **heap** is a complete binary tree that keeps one rule: **every parent is ≤ both its
children** (a min-heap). That's much weaker than a BST — it says nothing about left vs
right, only parent vs child. So the smallest item is guaranteed to sit at the root, and
nothing else is guaranteed at all.

Because the tree is *complete* (every level full, last level filled left to right) it needs
no pointers. Store it in an array and compute the links:

```
        2            [2, 5, 4, 8, 9]
       / \            0  1  2  3  4
      5   4
     / \            children of i: 2i+1, 2i+2
    8   9           parent   of i: (i-1)/2
```

**Insert**: append at the end, then *sift up* — while you're smaller than your parent, swap
with it. **Remove-min**: take the root, move the *last* element into the root, then *sift
down* — while you're bigger than your smallest child, swap with it. Both walk one
root-to-leaf path, so both are `O(log n)`. Peeking the minimum is `O(1)`: it's `arr[0]`.

That is exactly what a chess engine wants for move ordering — "give me the most promising
move next", without ever sorting the whole list.

**Q1.** Append: `[2, 5, 4, 8, 9, 3]`, `3` at index 5. Parent is index 2 (`4`); `3 < 4`, so
swap → `[2, 5, 3, 8, 9, 4]`, now at index 2. Parent is index 0 (`2`); `2 < 3`, so stop.
Final: **`[2, 5, 3, 8, 9, 4]`**.

**Q2.** Root `2` leaves. Last element `4` moves to the root: `[4, 5, 3, 8, 9]`. Children of
index 0 are `5` and `3`; the smaller is `3`, and `3 < 4`, so swap → `[3, 5, 4, 8, 9]`, now
at index 2. Index 2 has no children (5 and 6 are past the end), so stop. Final:
**`[3, 5, 4, 8, 9]`**.

`O(log n)` because a sift only ever moves along one path from root to leaf, and a complete
tree of `n` nodes is `log₂ n` levels deep — 20 levels at a million items, not a million
steps. Same reason as yesterday's halving loop.
