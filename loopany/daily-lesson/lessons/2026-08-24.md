### Concept

`if let` is a `match` with one arm you care about and no `_` to write.

```rust
if let Some(word) = optional_target {
    // `word` is the value inside — and only in here
}
```

The left-hand side is a **pattern**, not a variable. `Some(word)` matches only when the
`Option` is `Some`, and binds what's inside to `word`. On `None` the block is skipped.

`while let` is the same trick in a loop — keep going while the pattern still matches:

```rust
while let Some(x) = stack.pop() {
    // stops the first time pop() returns None
}
```

That's the idiomatic way to drain anything that hands values back as `Option`.

## Track B · DSA

### Concept

Third pass on this pair, so let's come at it from the other side. Same recursion, two
storage shapes:

- **Memoization — top-down.** Recurse normally; before computing, look the argument up; after
  computing, write it. Entries appear in the order calls *return*, and only for arguments the
  recursion actually reached. **Sparse and lazy.**
- **Tabulation — bottom-up.** No recursion at all: a loop filling the table from the smallest
  case upward, so every entry below the target gets computed whether anything needed it or
  not. **Dense and eager.**

A transposition table is a memo. Q2 is about *why it can't be a table*.

**Q2 (a).** `0, 1, 2, 3, 4, 5` — index order, smallest first, all of them. The memo wrote
`2, 3, 4, 5` (the base cases return without a write, and 5 lands last). Bottom-up is complete

**(b)** Either reason counts. There is no "smallest first" — positions don't form a chain
where `n` depends on `n-1`; they form a graph, and there's no cheap total order to sweep. And
even if there were, the space is ~10⁴⁰ positions while a 3-ply search visits a few thousand.
Bottom-up computes everything; a search can only afford what it visits.
