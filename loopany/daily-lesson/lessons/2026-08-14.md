## Track A · Rust

### Concept

`mod` makes a file part of the crate. `use` is separate — it only shortens a path you could
already write:

```rust
pub mod piece;                       // compiles the file
use piece::Piece;                    // now `Piece` instead of `piece::Piece`
```

`as` renames on the way in, for when two paths collide or the name is unwieldy:

```rust
use self::fruits::PEAR as fruit;
```

The third form is the one `modules2` actually needs. A plain `use` is **private** — it brings
the name into *this* module only. `pub use` re-exports it: the name becomes part of this
module's public surface, so outside code can reach it here too. That's how a crate offers
`chess::Piece` while the code lives in `chess/piece.rs`.

## Track B · DSA

### Concept

Phase 2 needs move generation, and the standard representation is a **bitboard**: one `u64`
where bit `i` means "something is on square `i`". Same numbering as your `Square` — bit 0 is
a1, bit 63 is h8, `index = rank * 8 + file`.

A board is ~12 of these (one per piece kind per colour). The payoff is that set operations
become single instructions:

```
white_pawns & rank_4        squares where both are true   (intersection)
white | black               all occupied squares          (union)
!occupied                   all empty squares             (complement)
white_pawns << 8            every white pawn moved one rank up
```

That last one is the trick worth seeing. Shifting left by 8 moves every bit up one rank at
once — one operation generates *all* pawn pushes, no loop. `count_ones()` (popcount) counts
set bits, which is your material count.

The catch is the edges. `<< 8` is safe: bits shifted past 63 fall off, which is correct —
pawns can't leave the board. But `<< 1` (one square east) is **not** safe: the bit on h1
(bit 7) becomes bit 8, which is a1 — it wraps onto the next rank. Sideways shifts need a file
mask to delete the wrapped bits.

<summary>Worked answer — open only after you've written yours</summary>

**Q1.** Bits 8–15 set is `0x000000000000FF00`. Shifted: `0x0000000000FF0000` — the same eight
bits, now at 16–23, which is rank 3. It represents **every white pawn advanced one square**,
computed in one operation instead of eight.

(It's not yet a legal move list — it says nothing about whether those squares are occupied.
The real generation is `(pawns << 8) & !occupied`.)

**Q2.** `0x42` = `0100 0010`, so bits **1** and **6**. `rank = i / 8` is 0 for both, `file =
i % 8` gives 1 and 6 → **b1 and g1**: the white knights on their starting squares. Popcount
is **2**.

`0x80` is bit 7 = **h1**, the last square of rank 1. `<< 1` makes it bit 8 = **a1** — it
didn't move one square east, it teleported to the far side of the next rank. Shifting is
arithmetic on a 64-bit number; it has no idea the board wraps. Every east shift has to drop
the h-file first: `(bb & !FILE_H) << 1`. West shifts mask the a-file.

</details>
