# Lesson 1 · `let` — every value needs a name

*Phase 1 · Rust foundations. ~5 min read, ~10 min doing.*

## Concept

In Rust you never introduce a variable by just assigning to it. A new name is
*bound* to a value with `let`, and by default that binding is **immutable** —
once bound, the value can't change.

```rust
fn main() {
    let x = 5;          // binding, immutable
    println!("x = {x}"); // {x} interpolates the variable directly
    // x = 6;           // ← compile error: cannot assign twice to immutable variable
}
```

Want it to change? You have to say so out loud: `let mut x = 5;`. That's the
whole idea behind Rust's reputation — the *default* is the safe one, and you opt
into mutation explicitly. You'll lean on this every day for the rest of this
course; it's the seed of the ownership rules that make the linked list in Phase 2
possible.

One more thing you just used: `println!` ends in `!` because it's a **macro**,
not a function. Macros are expanded at compile time, which is how `println!` can
type-check your format string.
