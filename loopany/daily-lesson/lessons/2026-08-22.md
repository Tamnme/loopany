## Track A · Rust

### Concept

`Option<T>` is how Rust says *there might not be a value here*. It is an ordinary enum with two
variants:

```rust
enum Option<T> {
    Some(T),   // there is a value, and here it is
    None,      // there isn't one
}
```

No nulls, no sentinel `-1`. If a function might have nothing to give back, it says so in its
return type, and every caller has to deal with both cases before it can touch the value.

You have already used one: `Piece::from_char` returns `Option<Piece>` because `'x'` is not a
piece. `Board::piece_at` returns `Option<Piece>` because a square can be empty.

Getting the value out: `match` on it, or — when you're certain and it's a test — `.unwrap()`,
which hands back the `T` and panics on `None`.

## Track B · DSA

### Concept

Two ways to stop a recursion recomputing the same thing.

Naive `fib(6)` calls `fib(4)` twice, `fib(3)` three times, `fib(2)` five times — the tree is
exponential even though there are only **7 distinct answers**.

**Memoization** is top-down: keep recursing, but write each answer into a table and check the
table before you recurse.

```
fib(n):  if n in memo: return memo[n]
         memo[n] = fib(n-1) + fib(n-2)
         return memo[n]
```

**Tabulation** is bottom-up: skip the recursion, fill the same table with a loop from the base
cases upward.

```
table[0] = 0; table[1] = 1
for i in 2..=n: table[i] = table[i-1] + table[i-2]
```

Same table, same arithmetic. The difference is *who* decides the order: the call stack, or you.

This is the phase-7 idea in miniature — a transposition table is memoization on a game tree,
where the same position keeps turning up by different move orders.

<details>
<summary>Worked answer — open only after you've written yours</summary>

The descent goes `6 → 5 → 4 → 3 → 2`, and `fib(2)` is the first call that can finish: both its
children are base cases. So the **write** order is

```
memo[2]=1, memo[3]=2, memo[4]=3, memo[5]=5, memo[6]=8
```

Five writes (`0` and `1` are base cases, not computed). Tabulation fills `i = 2,3,4,5,6` — the
**same order**.

That's the point: memoization discovers the bottom-up order by descending to the bottom first.
The order is identical; the difference is the call stack, which tabulation doesn't pay for.

Tabulation is faster and has no stack-depth limit. Memoization wins when you don't need every
entry — and in chess you very much don't: a search visits a thin slice of the legal positions,
so a table you fill lazily by descending is the only shape that works.

</details>
