## Track A · Rust

### Concept

`quiz2` is the first exercise where the **test tells you the signature** and you have to read
it back out. You wrote:

```rust
pub fn transformer(input: &[HashMap<String, Command>]) -> [String]
```

Two problems, both fixed by the test. It calls `transformer(input)` where `input` is a
`vec![(String, Command), ...]` — a `Vec` of **tuples**, not maps, and passed **by value**. So
the parameter is `Vec<(String, Command)>`.

And `[String]` can never be a return type: a bare slice has no size the compiler can count at
compile time, so it can't live in a return slot. The owned, growable version is what you
already have — `Vec<String>`.

```rust
pub fn transformer(input: Vec<(String, Command)>) -> Vec<String> {
```

Then `for (text, command) in input` destructures each tuple, and `match command` picks the
transformation.

## Track B · DSA

### Concept

Minimax looks at every leaf. Alpha-beta skips the ones that **cannot change the answer**.

Take yesterday's tree. `B1 = min(+3, +5) = +3`, so White already has a guaranteed **+3** — a
floor. Now start on `B2` and read its first leaf, `-1`:

```
              White (max)   floor is +3 after B1
             /           \
        B1 (min) = +3   B2 (min)
        /    \         /    \
      +3     +5      -1     +8   <- never looked at
```

`B2` is a **min** node, so whatever else is under it, `B2` can only get *smaller* than `-1`.
It is already worse than White's +3. White will never play into `B2` — so the `+8` never needs
scoring. One leaf saved, and the answer is unchanged: still `+3`, still B1.

That's the whole trick: keep the best value found so far, and cut a branch the moment it can't
beat it.
